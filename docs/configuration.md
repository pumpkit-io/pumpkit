# Configuration

Every setting comes from one `.env` file at the repo root, copied from `.env.example`. `sh scripts/setup.sh` writes it with database, signing and encryption secrets plus a persistent trial identity key ring generated, asking for (or, without a terminal, naming) each missing required value and keeping every value already there; `--help` lists its flags. Every service reads it: the dev stack in `compose.dev.yml` passes it to the backend and the publisher, and the Vite dev server reads it from the repo root.

Only the settings under [Required](#required) must be set. Everything else is optional: leave it unset or empty and the app boots with the default shown, or with that provider off.

Active optional provider groups are Stripe billing (`STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `STRIPE_WEBHOOK_SECRET`, `BILLING_PLAN_KEYS`), operator details (`OPERATOR_NAME`) and PostHog (`POSTHOG_PROJECT_API_KEY`). With all required group settings present, the provider is on; with none it is off; a partial group refuses startup. Retained inactive Google and SMTP groups are still validated for coherence, but credentials never activate their routes. X is required separately. `SUPPORT_EMAIL` stands alone, except that operator details require it for the company footer's contact address.

## X account trial eligibility

`TRIAL_IDENTITY_KEYS` is a secret JSON key ring, separate from the Coupon ring:
`{"active":"v1","keys":{"v1":"<base64 of 32 random bytes>"}}`.
Generate each key once with `openssl rand -base64 32`, choose an explicit key identifier,
and protect the complete ring like the database credentials. Every instance requires a valid ring at startup, including one without plans. Setup generates its initial key only when absent; rerunning setup preserves it.

An X account can receive at most one introductory trial per instance. Subscription
history removes eligibility even if the subscription ended or its first payment failed,
matching the existing billing rule. Failed or abandoned checkout attempts alone do not
consume eligibility. Confirmed coupon benefits also permanently remove eligibility. Different X accounts keep separate histories when they share email.

The `trial_eligibility` table keeps only a keyed fingerprint of the stable X ID, its key
identifier and eligibility state. Ordinary account deletion preserves it for the lifetime
of the instance, independently of the deleted profile, contact email, posts and publishing
credentials. The fingerprints remain pseudonymous personal data. Coupon claim records keep their separate retention and purge contract.

Back up the complete ring encrypted, separately from the database, and restore its
matching copy with every database restore. Rotate by adding a new key under a new ID and
changing `active`, while retaining every old key used by retained records or backups.
Never reuse an ID for different bytes or discard historical keys. Missing or invalid
keys make an unproven eligibility decision fail closed with a 503, rather than offering a
new trial. Proven ineligibility stays ineligible. Recording further ineligibility uses the
current key, so a lost historical key does not block settled account deletion or non-trial
billing. Restore the keys to recover; deleting eligibility rows is not a rotation or recovery
procedure. Migration `0056` refuses downgrade while retained eligibility exists.

## Personal local development

Use `scripts/dev-stack up --personal` for persistent personal data, real X and
Stripe's sandbox at `http://localhost:5173`. Agent stacks remain emulated.
[Setup and webhook forwarding](agents/dev-stack.md#personal-testing-on-localhost-with-real-providers)
cover the sandbox catalog, coupon settings and separate volumes.

`X_LOCAL_CALLBACK_RELAY` defaults to `false`. Personal mode enables it for both
the backend and Vite: the X redirect URI becomes
`http://127.0.0.1:PORT/oauth/x/callback`, while `PUBLIC_URL` and all other app URLs
remain `http://localhost:PORT`. It requires `ENV=local` and an HTTP localhost
origin with an explicit port; production rejects it. The Vite development server
forwards only X's authorization response to the fixed localhost callback. Setting
this flag on a production web server does not install a relay.

## URLs derived from `PUBLIC_URL`

None of these is a setting. A trailing slash on `PUBLIC_URL` is dropped.

| ----------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Frontend                      | `PUBLIC_URL`                                                    | Redirects back to the app after sign-in.                                                                                                                                                                                                                                                                                                                                                  |
| API                           | `PUBLIC_URL/api/v1`                                             | The frontend calls it on its own origin, including the X sign-in start and completion endpoints.                                                                                                                                                                                                                                                                                          |
| CORS origins                  | `PUBLIC_URL`                                                    | The only origin allowed to call the API from a browser.                                                                                                                                                                                                                                                                                                                                   |
| X redirect URI                | `PUBLIC_URL/oauth/x/callback`                                   | Register it as a callback URL on the X app. Personal mode uses the loopback relay exception above.                                                                                                                                                                                                                                                                                        |
| Stripe Checkout return        | `PUBLIC_URL/billing/success` and `PUBLIC_URL/billing/cancelled` | Where Checkout returns after paying or cancelling.                                                                                                                                                                                                                                                                                                                                        |
| Stripe customer portal return | `PUBLIC_URL/billing`                                            | Where the customer portal returns.                                                                                                                                                                                                                                                                                                                                                        |
| Stripe webhook                | `PUBLIC_URL/api/v1/stripe/webhook`                              | Register it as the webhook endpoint in Stripe.                                                                                                                                                                                                                                                                                                                                            |
| MCP endpoint                  | `PUBLIC_URL/api/v1/mcp`                                         | AI apps connect to it by signing in with OAuth, with nothing to configure: Pumpkit is its own authorization server and serves its discovery documents under `PUBLIC_URL/.well-known/`. | Canonical and social URLs     | `PUBLIC_URL/`                                                   | The web container writes them into `index.html`'s canonical, Open Graph, Twitter card and JSON-LD tags, and into `sitemap.xml`, when it starts.                                                                                                                                                                                                                                           |

The scheme of `PUBLIC_URL` also decides the sign-in cookies. With `https` they are `Secure`, and the refresh cookie is named `__Host-refresh_token` and X browser-binding cookie `__Host-x_sign_in_browser`; with `http` they are plain and the refresh cookie is `refresh_token`, because Safari drops `Secure` cookies on `http://localhost`.

### Author lookups

Adding an Inspiration author whose handle isn't in the Author directory first looks its profile up on twitterapi.io (ADR 0019). An account found and public joins the directory for good; a missing, suspended or private one is remembered for every User. Picking from the directory and answering from a remembered miss never count towards a limit, and nor does refreshing an author's posts, which keeps its cooldown of a day per handle. Over a User's limit, adding answers 429 with the minutes until the oldest counted lookup leaves the hour or the day; over the Instance's cap, it answers that lookups are paused for today.

| Variable                                                  | Meaning                                                                                                                                                                                            |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTHOR_LOOKUP_HOURLY_LIMIT`, `AUTHOR_LOOKUP_DAILY_LIMIT` | Lookups each User may run in any hour and in any 24 hours. Default to 10 and 30.                                                                                                                   |
| `AUTHOR_LOOKUP_INSTANCE_DAILY_LIMIT`                      | Lookups the whole Instance may run in any 24 hours, a ceiling on twitterapi.io spend. Defaults to 500.                                                                                             |
| `AUTHOR_MISS_DAYS`                                        | Days a handle that isn't on X, or is suspended, answers "@handle isn't on X" without a lookup. Defaults to 7.                                                                                      |
| `AUTHOR_PRIVATE_MISS_DAYS`                                | Days a private account answers that it's private without a lookup. Defaults to 1, so it can be added soon after it goes public.                                                                    |
| `AUTHOR_POSTS_REUSE_DAYS`                                 | Adding an author reuses posts any User fetched within this many days instead of fetching them again, and a fetch that found no posts answers that the account has none for as long. Defaults to 7. |

Each fetch of an author's posts updates its directory entry's photo, and its name too, except for a seeded account, which keeps the name it was seeded with.

`GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`, SMTP (`SMTP_HOST`, `EMAIL_FROM`, `SMTP_SECURITY`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`) and `GRAVATAR_ENABLED` belong only to retained Google/magic link implementations. ## Coupons (implementation contract)

Coupon runtime settings are introduced by #395, not by the legal-document update. [The coupon contract](coupons.md) defines the default-off `COUPONS_ENABLED` setting, the secret `COUPON_IDENTITY_KEYS` key ring, backup/rotation, daily purge and the final Stripe activation gate. Do not enable the feature before all implementation tickets and final #394 are complete. Billing-disabled instances need none of this configuration.

## Coupon configuration

`COUPONS_ENABLED` defaults to `false`. It gates issuance, preview, redemption, future paid signup and deferred billing frequency changes. Keep it off outside isolated tests until final #394 validates the merged implementation. Existing billing and instances selling no plans keep their behavior.

`COUPON_IDENTITY_KEYS` is a secret JSON key ring: `{"active":"v1","keys":{"v1":"<base64 of 32 random bytes>"}}`. Enabling coupons requires a valid ring and issuing requires configured Stripe plans. All configured offers must resolve to the same offer name and currency, with one-month or one-year intervals. Missing or incompatible prices prevent issuance. This check reads the existing billing catalog and creates no payment or subscription.

Store the ring in the same protected instance configuration used by the backend and privileged command. Back it up encrypted separately from the database, restore the matching complete ring with the database, and retain old keys for existing fingerprints and backups. Never replace key bytes under an existing identifier. See [key custody and rotation](coupons.md#identity-and-key-custody) and [the commands](coupons.md#privileged-coupon-commands).

`STRIPE_COUPON_PORTAL_CONFIGURATION_ID` names an active Stripe management-only portal configuration with subscription updates, subscription cancellation and its login page disabled. Enable payment-method management/invoice history as needed. Every restricted session validates the current provider configuration and names it explicitly; an unsafe or missing configuration refuses the session. Enabled instances use it for ordinary paid subscribers too, with cancellation available in Settings. It is optional while coupons stay off, and adds no second feature switch. See [portal activation safeguards](coupons.md#portal-and-activation-safeguards): changing the ID alone does not revoke old sessions. Final #394 must validate existing-session treatment before activation.

The [merged coupon validation report](stripe-coupon-verification.md) records real test-mode Checkout, renewals, the classic interval correction and authenticated reminder previews. Coupons remain off: #430 must establish a safe transition for outstanding portal confirmations before activation. Generic trial reminders were off when inspected and must not describe coupon access as a new introductory trial.
